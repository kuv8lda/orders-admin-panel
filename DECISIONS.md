# Технические решения

## Развёртывание и безопасность

- Один процесс gunicorn с потоками: ограничение попыток входа хранится в памяти процесса.
- `TRUST_PROXY=1` включает `ProxyFix(x_for=1)`: доверяем одному обратному прокси.
- `COOKIE_SECURE` позволяет локальный запуск по HTTP без отключения остальных защит.
- HSTS не содержит `includeSubDomains`, чтобы не затрагивать другие поддомены.
- Сессии хранятся в подписанных cookie. При входе `session.clear()` очищает прежнее содержимое, затем создаётся новый CSRF-токен.
- `/healthz` расположен вне `/api/`: проверка доступности не требует авторизации и не обращается к базе.

## Интерфейс

- Chart.js и используемые иконки Font Awesome хранятся локально: для статики не нужны CDN, CSP разрешает только свой origin.
- Иконки собраны из SVG в CSS через `scripts/build_icons.py`, без загрузки шрифтов.
- API возвращает английские сообщения; интерфейс переводит их через `js/i18n.js`, не меняя контракт API. Решения по оформлению — в [DESIGN.md](DESIGN.md).

## Заказы и интеграции

- Панель и бот используют общий `_transition_order`: правила смены статуса и запись события не дублируются.
- Цену заказа рассчитывает панель; позиции заказа сохраняют снимок названий и цен.
- `idempotency_key` защищён уникальным индексом: SQLite не поддерживает добавление уникального столбца через `ALTER TABLE ... ADD COLUMN`. Повторная доставка возвращает существующий заказ.
- Лента событий использует курсор по `order_events.id`, а не времени: события с одинаковой отметкой времени не теряются на границе страницы.
- Удаление персональных данных реализовано анонимизацией: заказы, суммы и история статусов сохраняются. Повторный запрос безопасен.

Маршруты, форматы ответов и ограничения описаны в [README.ru.md](README.ru.md).
